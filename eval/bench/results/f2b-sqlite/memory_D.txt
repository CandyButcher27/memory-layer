## ISS-1 — sqlite-utils 4.2 crashes on startup without dev dependencies
Symptom: `sqlite-utils` 4.2 crashed on import when installed without the dev group (issue #842); `typing_extensions` was imported in `sqlite_utils/db.py` but is not a runtime dependency.
Cause: `from typing_extensions import Self` for `Database.__enter__` annotation; dev group masked the missing dependency in tests.
Fix: f6d7311 (released 4.2.1, 28dc627). CI smoke test `uv run --no-default-groups sqlite-utils --help`, also `just test-no-dev-dependencies` (56dd097).
Test: CI step "Check no accidental dev= dependencies needed" in `.github/workflows/test.yml`
Status: fixed

## ISS-2 — SpatialLite apt install 404s in CI
Symptom: CI `apt-get install libsqlite3-mod-spatialite` failed with a 404 fetching libminizip1t64 from security.ubuntu.com.
Cause: stale apt package lists on the runner image; the old .deb was pulled from the mirror.
Fix: f7e3174 (test.yml), 85b1be1 (test-coverage.yml): `apt-get update && apt-get install -y`.
Test: CI SpatialLite install step
Status: fixed

## ISS-3 — ResourceWarning from buffered readers in rows_from_file
Symptom: unclosed-file ResourceWarnings under `pytest -Wall` (spotted in a downstream project's `just test -Wall`).
Cause: format-detection buffered wrapper in `sqlite_utils/utils.py` was never closed.
Fix: 6bc1d33
Test: tests/test_rows_from_file.py
Status: fixed

## ISS-4 — transaction cleanup masked IntegrityError
Symptom: `OperationalError: no such savepoint` / `cannot rollback - no transaction is active` raised instead of the original `sqlite3.IntegrityError` after a RAISE(ROLLBACK) trigger or INSERT OR ROLLBACK in `atomic()`/`query()`.
Cause: those errors destroy the whole transaction and its savepoints; cleanup tried to roll back anyway.
Fix: d9a0fd2 (cleanup checks `conn.in_transaction` first)
Test: tests/test_query.py
Status: fixed

## ISS-5 — tests catching stdlib sqlite3 exceptions fail under sqlean
Symptom: test_create_table_compound_foreign_key_enforced failed with sqlean installed.
Cause: sqlean's IntegrityError is not a subclass of stdlib `sqlite3.IntegrityError`.
Fix: 658185d (import sqlite3 from `sqlite_utils.utils` in tests). sqlean support later removed in afbfd95.
Test: tests/test_foreign_keys.py
Status: fixed

## DEC-1 — Database() rejects Python 3.12+ autocommit= connections
Why: with `autocommit=True` commit() is a no-op and with `autocommit=False` the connection is always in a transaction; library writes looked fine in-process but were discarded on close. Raising TransactionError beats silent data loss.
Rejected: supporting both modes — writes silently lost.
Reverse if: the library adapts its transaction handling to the PEP 249 autocommit attribute.
Date: 2026-07-04 (bcd9a26)

## DEC-2 — Database context manager rolls back on exit instead of committing
Why: open transactions only come from manual transaction control; auto-committing could persist half-finished work. Deliberately differs from sqlite3.Connection's context manager.
Rejected: commit on exit like sqlite3.Connection — persists partial work.
Reverse if: none recorded.
Date: 2026-07-04 (6c88067)

## DEC-3 — rejected write PRAGMAs in db.query() are documented, not fixed
Why: some PRAGMAs cannot run inside a transaction, so they run outside the savepoint guard; e.g. `PRAGMA user_version = 5` takes effect despite the ValueError. A fix would need a hardcoded list of row-returning PRAGMAs.
Rejected: hardcoded PRAGMA list — maintenance burden.
Reverse if: SQLite exposes a reliable way to tell row-returning PRAGMAs apart.
Date: 2026-07-06 (6693491, refs issue #769)

## DEC-4 — insert_upsert_implementation keeps its 36-parameter signature; only type hints get added
Why: plugins call `insert_upsert_implementation` directly, so it is effectively public API; replacing the parameters with a dataclass would break them. Decided with Simon (maintainer), 2026-10-04.
Rejected: dataclass for the parameters — breaks plugin callers.
Reverse if: a deprecation path for plugin callers is agreed.
Date: 2026-10-04

## Tests fail on old SQLite 3.23.1 in the SQLite-version CI matrix
`test-sqlite-support.yml` runs against SQLite 3.46 and 3.23.1 (2018, before UPSERT). 3.23.1 has no RETURNING (needs 3.35; 2582446), rejects a UTF-8 BOM before the first token, and before 3.36 selecting rowid from a view returns NULL instead of erroring (c2a1774). Use `sqlite_master`, not `sqlite_schema`, for older SQLite (b432e68).

## Runtime import of a dev-only package crashes the installed CLI
Dev dependency groups hide missing runtime deps in tests (4.2 crash, ISS-1). Check with `just test-no-dev-dependencies` (`uv run --isolated --no-default-groups sqlite-utils --help`).

## Cog check fails with older click
`cog --check` in `just lint` needs click>=8.4.2, pinned in dev deps (79117b9, issue #761).

## `just docs` fails with "refusing to fetch into branch 'refs/heads/main'"
Fixed by a workaround in `docs/conf.py` (5f81752); the author notes they do not understand why it works, so do not simplify it away.

## Nightly analyze-tables job to Slack is blocked on prod access (SEC-2210)

The command only takes a local file path (`exists=True`, cli.py:3032), so the job must fetch a copy first. Output is plain text, no JSON mode (cli.py:3074-3137); do not use `--save` on prod, it writes `_analyze_tables_` into the DB.
