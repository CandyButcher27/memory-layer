## DEC-1 — Database() rejects Python 3.12+ autocommit=True/False connections
Why: with `sqlite3.connect(autocommit=True)` commit() is a no-op and with `autocommit=False` the connection is permanently in a transaction; in both modes this library's writes appeared to work but were silently discarded on close (bcd9a26).
Rejected: accepting them silently — data loss.
Reverse if: the library is reworked to manage transactions under the PEP 249 autocommit attribute.
Date: 2026-07-04

## DEC-2 — Database context manager rolls back on exit instead of committing
Why: exit is equivalent to close(); an open transaction can only come from manual transaction control, and auto-committing could silently persist half-finished work. Deliberately differs from sqlite3.Connection's context manager (6c88067, docs/python-api.rst).
Rejected: commit on exit like sqlite3.Connection — persists partial work.
Reverse if: the transaction model changes so open transactions can arise implicitly.
Date: 2026-07-04

## DEC-3 — Vendor the setup-sqlite-version GitHub Action
Why: the upstream asg017/sqlite-versions action (pinned at 71ea0de) failed on sqlite.org timeouts; vendoring allowed hardening it (02281f7, issue #774).
Rejected: depending on the upstream action — flaky CI.
Reverse if: upstream gains the same timeout robustness.
Date: 2026-07-05

## DEC-4 — Production writes use `--upsert` with an explicit `--pk`, never `--replace`
Why: `--replace` (INSERT OR REPLACE) deletes and re-inserts the whole row, and once wiped the user's enrichment columns in production (told 2026-10-04; incident date and reference not given). `--upsert` only sets the columns present in the input.
Rejected: `--replace` — loses columns absent from the input.
Reverse if: the user lifts the rule.
Date: 2026-10-04

## DEC-5 — `--sample N` uses `order by random() limit N`, and is mutually exclusive with `--order`
Why: a random-offset approach (`offset abs(random()) % count` per row) was tried by the user and returned duplicate rows and does not work on WITHOUT ROWID tables (told 2026-10-04). `Table.rows_where(sample=)` also raises ValueError when combined with order_by, limit or offset; the CLI `--sample` must error when given with `--order`.
Rejected: per-row random offset — duplicates, breaks on WITHOUT ROWID.
Reverse if: the user lifts the rule.
Date: 2026-10-04

# External systems
Last verified: 2026-10-04

## Ubuntu runner apt lists are stale, apt-get install 404s
GitHub's ubuntu-latest image can ship outdated apt lists; any `apt-get install` step must run `apt-get update` first (ISS-3, f7e3174, 2026-09-01).

## sqlite.org downloads time out in the SQLite-versions CI job
The "Test SQLite versions" workflow builds SQLite from sqlite.org via the vendored `.github/actions/setup-sqlite-version`; sqlite.org timeouts were the reason it was vendored (DEC-3, issue #774). The job is `continue-on-error: true`.

## Dev-only dependencies mask missing runtime dependencies
Tests run with the dev group installed, so an import that only the dev group satisfies passes CI but crashes users (ISS-1, issue #842). Check with `uv run --no-default-groups sqlite-utils --help`.

## Ingest service runs sqlite-utils on AWS Lambda, only /tmp is writable
The user's ingest service runs `sqlite-utils` on Lambda and creates all databases under /tmp (told 2026-10-04). The CSV path itself writes no temp files (no `tempfile` use in `sqlite_utils/*.py`, grep 2026-10-04); SQLite's own temp files are unchecked, `SQLITE_TMPDIR=/tmp` may be needed for large inserts.

## Vendor CSV exports are semicolon-delimited with a UTF-8 BOM
Vendor exports use `;` and start with a BOM (told 2026-10-04). Forgetting `--delimiter ';'` has put each whole row in one column more than once. `insert` defaults to `utf-8-sig`, so the BOM is stripped unless `--encoding utf-8` is passed explicitly. Delimiter is never guessed without `--sniff`; `--sniff` on these files is untested.

## Nightly 1.2M-row CSV insert takes 6m10s at default batch size
The user's nightly 1.2M-row CSV `insert` with default settings took 6m10s, median of 3 runs on 2026-09-18 (told 2026-10-04). Column count unknown, and the effective batch is capped at 999 // columns, so a larger `--batch-size` may change nothing. No other setting has been measured.

## sqlite-utils-geo plugin problems go to Dmitri
The internal plugin sqlite-utils-geo is maintained by Dmitri; plugin problems are routed to them (told 2026-10-04). First check: `sqlite-utils plugins` must list it.

## Reporting service stays on the 3.x API until Q1 2027
The reporting service is pinned to sqlite-utils 3.x until Q1 2027 because the dashboard team's code depends on the old upsert behaviour (told 2026-10-04). Upsert changes that matter are in the 4.0a0 and 4.0 changelog entries.

## Ingest database schema freeze is 2026-11-01
The user's ingest database schema freezes on 2026-11-01 (told 2026-10-04).

## SpatiaLite cannot ship in production, Lambda layer size limit
SpatiaLite is not shipped in production because of the Lambda layer size limit (told 2026-10-04). `--load-extension spatialite`, `init-spatialite` and `add-geometry-column` will fail there with "Could not find SpatiaLite extension".

## `uv run` fails: Multiple top-level packages discovered in a flat-layout
With `mimi/` in the repo root, setuptools refuses the editable build (`['mimi', 'sqlite_utils']`), so `uv run` fails (2026-10-04). Workaround: `uv run --no-project --with click --with click-default-group --with pluggy --with python-dateutil --with sqlite-fts4 --with tabulate python ...`. `python` is also absent on this WSL shell, use `python3`.
