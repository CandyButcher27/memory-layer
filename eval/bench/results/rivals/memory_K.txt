**You:** How does `--upsert` decide which rows match? By the way, we never use `--replace` in production: it once wiped our enrichment columns, so the rule is `--upsert` with an explicit `--pk`.
  - `Bash: grep -n "upsert\|\"--pk\"\|--replace" sqlite_utils/cli.py | head -40; grep -n "def upsert\b" -A30 sqlite_utils/db.py | head -60`
  - `Bash: grep -n "def build_insert_queries_and_params" -A75 sqlite_utils/db.py | grep -n -i "upsert\|pk\|UPDATE\|INSERT"`
  - `Bash: sed -n 4345,4440p sqlite_utils/db.py`
  - `Bash: sed -n 4440,4490p sqlite_utils/db.py`

**Claude:** `--upsert` matches rows on the primary key columns and nothing else. In `sqlite_utils/db.py` (`build_insert_queries_and_params`, ~L4430):

- **Match columns:** `--pk` (repeatable for compound keys) becomes `ON CONFLICT(<pk cols>)`. Column casing is resolved against the record's keys.
- **On a match:** `DO UPDATE SET col = excluded.col` runs for every non-PK column in the incoming record. Columns the record doesn't contain are left untouched. This is why upsert doesn't wipe enrichment columns. `--replace` uses `INSERT OR REPLACE`, which deletes the whole row first, so any columns not in the incoming data are lost.
- **When every column is part of the PK:** it becomes `DO NOTHING`.
- **Missing or NULL key:** if a record has no value for a PK column, or the value is NULL, it raises `PrimaryKeyRequired`. This is deliberate. A NULL never matches `ON CONFLICT`, so it would insert a duplicate row.
- **Old SQLite (< 3.24):** it falls back to `INSERT OR IGNORE` of the PK followed by an `UPDATE ... WHERE pk = ?`. The matching is the same.

Two caveats for your rule:

- **Existing tables:** `--pk` is only honoured at table creation. For an existing table, the `ON CONFLICT` target still has to be backed by a unique index or primary key in the schema. If your `--pk` doesn't match the real PK or a unique index, SQLite errors with "ON CONFLICT clause does not match any PRIMARY KEY or UNIQUE constraint".
- **Overwrite semantics:** a column present in the incoming batch is overwritten, including with `null` if the record has an explicit null. Only absent columns are preserved. If your incoming data carries empty versions of the enrichment columns, upsert will clobber them too.
