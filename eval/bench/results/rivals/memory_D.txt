## ISS-2 — Failed db.execute() write leaves a phantom transaction open
Symptom: after a write via `db.execute()` raised, every later write was captured by an implicit transaction nothing committed (#769 review comment 4900034150).
Cause: the failing statement opened an implicit transaction and the exception skipped the auto-commit path.
Fix: 7d86118 (rolls back when the failed statement opened the transaction)

Status: fixed

## ISS-3 — db.query("/* c */ COMMIT") or "; COMMIT" commits the caller's transaction
Symptom: inside `db.atomic()`, a comment- or semicolon-prefixed COMMIT committed the outer transaction and surfaced as a "no such savepoint" error instead of ValueError.

Fix: 87cf1c5 (first-token scanner `_first_keyword()`), adc10df (leading `;`)
Test: tests/test_query.py::test_query_prefixed_commit_does_not_commit_transaction
Status: fixed

## DEC-1 — Database context manager rolls back on exit instead of committing
Why: exit is equivalent to `close()`; open transactions there can only come from manual transaction control, and auto-committing could silently persist half-finished work. Deliberately differs from `sqlite3.Connection`'s context manager.
Rejected: commit on exit like sqlite3 — would persist partial work.
Reverse if: open transactions at exit become possible from library calls, not just manual control.
Date: 2026-07-04 (6c88067)

## DEC-2 — Rejected write PRAGMAs in db.query() still take effect (documented, not fixed)
Why: some PRAGMAs refuse to run inside a transaction, so they run outside the savepoint guard; `PRAGMA user_version = 5` takes effect despite the ValueError. A fix would need a hardcoded list of row-returning PRAGMAs.
Rejected: hardcoded PRAGMA list — maintenance burden.
Reverse if: SQLite exposes which PRAGMAs return rows, or a maintained list becomes acceptable.
Date: 2026-07-06 (6693491)

## DEC-3 — sqlean.py support removed
Why: removed in PR #772 (closes #771, refs #769); reason lives in those GitHub issues.
Rejected: keeping the sqlite3/sqlean shim.
Reverse if: see #771.
Date: 2026-07-05 (afbfd95)

## DEC-4 — Production writes use `--upsert` with an explicit `--pk`, never `--replace`
Why: told 2026-10-03: `--replace` once wiped the user's enrichment columns in production. `--upsert --pk` is the team rule.
Rejected: `--replace` — it caused the data loss above.
Reverse if: the user lifts the rule, or enrichment data stops living in the same table.
Date: 2026-10-03 (told by user; the incident itself is undated)

## DEC-5 — `--sample N` uses `order by random() limit N`; `--sample` and `--order` are mutually exclusive in the CLI
Why: told 2026-10-03: the user tried random-offset sampling (`offset abs(random()) % count` per row) the week before; it returns duplicate rows and does not work for WITHOUT ROWID tables. In `rows_where()`, `sample` raises ValueError if combined with order_by, limit or offset; the CLI must error if both `--sample` and `--order` are given.
Rejected: random offset per row — duplicates, breaks on WITHOUT ROWID tables.
Reverse if: the user lifts the rule, or a measured need for sampling large tables without a full sort appears.
Date: 2026-10-03 (the earlier attempt is undated)

# CI, packaging and docs build traps
Last verified: 2026-09-01

## apt-get install libsqlite3-mod-spatialite 404s in GitHub Actions
Runner images ship stale apt package lists; an old `.deb` (e.g. libminizip1t64) gets pulled from the mirror and the install 404s. Always `apt-get update` first. Fixed in test.yml by f7e3174 and in test-coverage.yml by 85b1be1 (2026-09-01).

## Import works in dev but crashes for PyPI users
Dev dependency groups mask missing runtime dependencies (4.2 shipped importing `typing_extensions`, see ISS-1). Run `just test-no-dev-dependencies` before release.

## Cog check fails with older Click
Cog output for `--help` text requires `click>=8.4.2` in the dev group (79117b9, #761, 2026-06-24). Click 8.3.1+ also removed the need for the Sentinel workaround (e66e82f, #666).

## Building a wheel fails on old setuptools
PEP 639 license expression in pyproject.toml needs `setuptools>=77` in build-system requires (397cdcc, 2026-07-04).

# Tests failing only on old SQLite versions
Last verified: 2026-08-11

CI (test-sqlite-support.yml) runs the suite against SQLite back to 3.23.1. Traps found there, all in #769 review / follow-ups:

## no such table: sqlite_schema
The `sqlite_schema` alias does not exist on old SQLite; use `sqlite_master` (b432e68, 2026-08-11).

## INSERT ... RETURNING is a syntax error
RETURNING needs SQLite 3.35+; tests using it must skip on older versions (2582446, 2026-07-06).

## UTF-8 BOM before the first token rejected
SQLite 3.23.1 rejects a leading BOM in SQL; BOM test variants skip there (c2a1774, 2026-07-06).

## Selecting rowid from a view returns NULL instead of erroring
Before 3.36, `select rowid` from a view returned NULL; tests must accept either behavior (c2a1774, 2026-07-06).
