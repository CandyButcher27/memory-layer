Every file in `mimi/memory/` gets one line above saying when to read it. A file with no line is never read. `index` appends each file's `##` headings to its line, so a task can match a trap by name, and marks a file that holds nothing yet as `— empty`: skip those.

Memory holds only what someone wrote down. When it has nothing on the question, that is not an answer: search `git log --grep`, the issue tracker and the code before concluding.

### What to write, and where
- Bug fixed → append to `mimi/ISSUES.md`: exact symptom text, cause, fix commit, test.
- Choice someone could argue again → append to `mimi/decisions.md`: why, what was rejected, what would reverse it.
- Fact the code cannot tell you → `mimi/memory/<topic>.md`: external-system quirks, measured numbers with date and sample size, why something non-obvious exists, environment traps. Give each trap its own `##` heading, named the way a task would describe it (error text, library, table, command). Keep one `Last verified:` line per file, dated when its facts were last checked.
- End of a work session → overwrite `mimi/STATE.md` (or run the `mimi-close` skill). Finished work leaves it.
- Code change alone → nothing. Git has it.

## DEC-1 — `cargo install` uses the package's `Cargo.lock` by default
Why: build/test used the lockfile while install re-resolved, so installs could pick untested versions and fail. Cargo team decision on rust-lang/cargo#7169; landed in #17388 (7941be6fb).
Rejected: keep lockfile opt-in via `--locked` — maintainers end up supporting untested dep versions
Reverse if: Cargo team revisits #7169. `--locked` is now accepted as a no-op; missing-lockfile warning still fires when passed explicitly.
Date: 2026-09 (commit 7941be6fb)

## DEC-2 — profile `trim-paths` accepts only `none|object|all`
Why: stabilization prep for `-Ztrim-paths`; other scopes and booleans deferred until needed. See rust-lang/cargo#12137 and #17432 (3c0b53475). Default is `none` (a82d93f0e).
Rejected: keeping the full scope list and boolean values — not needed for stabilization
Reverse if: a concrete need for another scope or boolean appears
Date: 2026-09 (commit 3c0b53475)

## DEC-3 — retry sleep constants in `src/util/network/retry.rs` keep raw integer units
Why: `MAX_RETRY_SLEEP_S` is `pub` and, per Ana on the cargo team, used by other crates, so changing its type would break them. Unit is already in each name suffix and doc comment, so no further change. In this repo the only user is `src/sources/git/utils.rs:1277`; external users were not checked.
Rejected: converting `MAX_RETRY_SLEEP_S`, `INITIAL_RETRY_SLEEP_BASE_MS` and the jitter to `Duration` — public API break
Reverse if: the external users are confirmed gone, or the cargo team accepts the break
Date: 2026-10-04 (told by user, no commit)

# Contribution process traps

Last verified: 2026-10-04

## PR ignored because the issue is not accepted
Only issues labeled `S-accepted` are reviewed. Source: CONTRIBUTING.md.

## LLM-assisted contributions
Cargo follows the rust-lang/rust LLM usage policy (https://forge.rust-lang.org/policies/llm-usage.html), including later updates. Source: doc/contrib/src/process/llm-usage.md.

## CI typos job fails
CI runs `typos`; check locally with `cargo spellcheck`, fix with `cargo spellcheck --write-changes`. Source: working-on-cargo.md.

Prefer atomic commits, with tests added in their own commit first showing current behavior (e.g. #13910, #14006). See git log 2c14149ce..694054f34 for the pattern. Source: working-on-cargo.md.

Not needed: Weihang said (2026-10-04, on the `net.retry` docs PR) that changelog entries are generated at release time. Do not add one in PRs.

# Testing traps

Last verified: 2026-10-04

## Snapshot assertion mismatch after changing output
Update file-backed and inline snapshots with `SNAPSHOTS=overwrite cargo test`, then review the diff. Source: doc/contrib/src/tests/writing.md "Updating Snapshots".

## Test silently ignored on stable
`#[cargo_test(nightly, reason = ...)]` tests are skipped off nightly; Cargo-only unstable features use `masquerade_as_nightly_cargo(&[...])` instead. Some nightly tests need `rustup component add rustc-dev llvm-tools-preview --toolchain=nightly`. Source: doc/contrib/src/tests/running.md, writing.md.

## Cross-compile tests fail without a 32-bit target
Install the 32-bit host target (e.g. `rustup target add i686-unknown-linux-gnu`, plus `gcc-multilib` on Ubuntu) or set `CFG_DISABLE_CROSS_TESTS=1`. Windows cross tests support MSVC only. Source: running.md.

## build-std, network and container tests never run by default
Opt in with `CARGO_RUN_BUILD_STD_TESTS=1` (nightly + rust-src, `--test build-std`), `CARGO_PUBLIC_NETWORK_TESTS=1`, `CARGO_CONTAINER_TESTS=1` (Docker; mostly broken on Windows, not run on macOS CI). Source: running.md.

## Running target/debug/cargo directly picks the wrong rustc under rustup overrides
Cargo changes directory per compilation, so a non-rustup-launched cargo can hit different toolchains. Use `rustup run nightly target/debug/cargo` or set `RUSTC`. Source: doc/contrib/src/process/working-on-cargo.md "Running Cargo".
