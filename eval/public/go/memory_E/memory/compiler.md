# Compiler (cmd/compile) and assembler/object layer

## Purpose
The gc compiler: Go source → object files consumed by `cmd/link`.

## Location
- `src/cmd/compile/README.md` — authoritative phase overview and contributor tips; read it first.
- `src/cmd/compile/internal/` — phases and per-arch backends (`amd64`, `arm64`, `riscv64`, ...).
- `src/cmd/internal/obj/` — assembler/machine-code generation, shared with `cmd/asm`.
- `src/cmd/link/internal/ld` (+ per-arch dirs, `loader`, `loadelf`/`loadmacho`/`loadpe`) — linker.

## Architecture
Pipeline (per README): `syntax` (parse) → `types2` (type check) → `noder` builds `ir` →
middle end (`inline`, `devirtualize`, `escape`, `deadlocals`, ...) → `walk` (order of evaluation,
desugaring) → `ssagen` converts to SSA → `ssa` passes, lowering, regalloc → `obj` emits code.
Export data is written from the unified IR (`noder`).

## Generated code
- SSA ops and rewrite rules live in `ssa/_gen/*.rules` and `*Ops.go` (generic + per-arch, plus
  `latelower`, `splitload`, `dec*`, `divmod` etc.). The `rewrite*.go` / `opGen.go` files in `ssa/`
  are generated: edit `_gen`, then `go generate` in `cmd/compile/internal/ssa` (runs
  `go run -C=_gen .`). `ssa/generate_test.go` fails if output is stale.
- `src/go/types` is largely generated from `cmd/compile/internal/types2` (files headed
  `Code generated by "go test -run=Generate -write=all"`). Change `types2`, then run
  `go test go/types -run=Generate -write=all`. Read `types2/README.md` before editing the checker.

## Configuration
- `GOEXPERIMENT` flags: struct `Flags` in `internal/goexperiment/flags.go` (run `go generate`
  after changing it — produces `exp_*_on/off.go`); per-platform defaults in
  `internal/buildcfg/exp.go`. The toolchain reads them via `objabi.Experiment` / `buildcfg`.
- Debugging: `-gcflags=-m` (escape/inlining), `-S`, `GOSSAFUNC`, `-d=...`; see README Tips.

## Testing
`go test cmd/compile/...`, `test/` via `cmd/internal/testdir`, `test/codegen` with
`-all_codegen`. See [[testing]].

## Important Constraints
- Must build with the bootstrap Go (1.26) — see [[build-bootstrap]].
- Compiler changes that affect codegen should get a `test/codegen` asmcheck; bug fixes usually get a
  `test/fixedbugs/issueNNNNN.go` regression test.
